没有原版 MacType 服务的电脑上，YMacType 现在自带服务；新增“应用启动器”，可以为 Chrome 等程序生成桌面快捷方式。

**新增**

- **自带服务宿主**：这台电脑上没有名为 `MacType` 的服务时，`YMacType.Settings.exe --install` 和概览页的“启动并修复服务”会创建一个（自动启动、LocalSystem）。服务为每个登录会话启动 32 位和 64 位两个钩子助手（`MacLoader.exe --hook`、`MacLoader64.exe --hook`），用 SYSTEM 令牌安装全局 `WH_GETMESSAGE` 钩子，让核心 DLL 加载进该会话的所有图形界面程序，包括管理员权限的程序。助手挂掉会自动重启，注销或停止服务时退出。日志在 `C:\ProgramData\MacType\Logs\service.log`。已经存在的 `MacType` 服务（例如原版的）不会被替换。
- **应用启动器页**：选一个程序（Chrome、Edge、Brave、Vivaldi、Opera、VS Code、Obsidian，或自己选择），在桌面生成快捷方式。快捷方式默认通过 `MacLoader` 启动，在程序入口处加载 YMacType，比事后注入覆盖得更早。Chromium 内核浏览器的快捷方式还会加上 `--disable-features=RendererCodeIntegrity`，否则官方 Chrome 的网页渲染器会拒绝加载未签名的模块。

**需要知道**

- 上面这个参数会关闭渲染器“只加载微软签名模块”的保护，等于少了一层沙箱防御，其它会注入的软件也能进入渲染器。页面里有说明，请自行权衡。
- 参数只对用这个快捷方式启动的浏览器生效。浏览器已经在运行时，新窗口会交给旧进程，需要先完全退出（包括托盘里的后台进程）。
- 新服务和钩子助手只在 Windows 上编译，没有实机测试过。装好后如果没有效果，请把 `service.log` 和设置面板“已生效应用”页的情况发给我。
- 服务只会从 `C:\Program Files\MacType` 启动助手，从别处复制出来的程序不会被当作服务运行。
